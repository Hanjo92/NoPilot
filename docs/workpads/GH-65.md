## Progress

- Audited the merged GH-63 chat panel paths covering command/view opening, prompt-history assembly, webview actions, and editor-apply behavior.
- Hardened `nopilot.openChatPanel` so it now focuses the actual `nopilot.chatView` first and only falls back to opening the NoPilot Activity Bar container if that focus command is unavailable.
- Extracted chat-panel request-history and apply-normalization logic into a dedicated `chatViewModel` helper so the risky behavior can be regression-tested outside the VS Code host.
- Fixed chat-history truncation so the panel now keeps up to the last ten prior turns after removing the current prompt instead of accidentally dropping one extra historical message.
- Fixed assistant-response storage so plain-code replies no longer lose leading indentation before the user applies them, while still collapsing blank-only responses to the existing fallback.
- Fixed assistant apply behavior so fenced code replies keep meaningful leading indentation, surrounding blank wrapper lines are removed without collapsing code, and empty fenced replies fail with an explicit error instead of silently inserting or replacing nothing.
- Fixed fenced-code extraction so apply/edit flows now recognize markdown info strings beyond simple word-only language tags, including forms like `c++` or metadata-bearing fences.
- Hardened chat prompt assembly so exact NoPilot control tags inside user prompts, selected code, editor context, or chat history are defanged before they are inserted into the prompt template, preventing prompt-structure collisions.
- Hardened the Ollama-specific inline prompt template so provider-local context blocks now defang those same control tags instead of leaving one prompt path structurally injectable.
- Added source coverage for the new focus fallback and helper wiring, plus an executable runtime regression test for chat-history trimming and apply normalization.
- Added `GH-65-finish.sh` and `GH-65-finish.test.sh` so the GitHub `Done` label transition and marker-tagged workpad comment sync are ready as soon as GitHub access is restored.
